Simplicity Bias in Attention

Jyo Pari, Shivam Duggal, Rafael Hanashiro, Lucas Torroba-Hennigen
Pulkit Agrawal, Yoon Kim

Occam’s razor suggests preferring the simplest explanation that fits the observations. Intuitively, an explanation is simpler if we can describe it more concisely. But this depends on the representation: the same function can have a short description in one form and a long description in another.

Minimum description length (MDL) turns this intuition into a tradeoff. We describe the model, then describe the data using that model. A more complicated model costs more to describe, but may help us describe the data more efficiently. With fixed encoding rules, let \(L(h)\) be the length in bits of a candidate model \(h\), and \(L(D\mid h)\) the length of dataset \(D\) encoded using it. Two-part MDL selects

\[ h_{\mathrm{MDL}}\in\arg\min_h\left[L(h)+L(D\mid h)\right]. \]

Simplicity bias has been studied extensively in feedforward networks. Huh et al. show how linear overparameterization can encourage representations with lower effective rank without changing expressive capacity. Weight decay encourages smaller weights, with theory in a specialized setting connecting minimum weight norms to algorithmic complexity in fixed-precision looped networks. These suggest keeping the parameterization flexible and guiding learning toward simpler solutions.

In attention, however, we usually fix the rule that converts query–key similarity scores into attention weights, choosing a particular form such as linear or softmax attention. What biases do these choices introduce? Can we find a more general formulation of attention, and revisit how to guide learning toward simpler solutions within it?

Linear attention and softmax

We use bold lowercase for vectors, bold uppercase for matrices, and ordinary italic for scalars. Let \(\mathbf{q}\) be a query, and let \(\mathbf{k}_i\) and \(\mathbf{v}_i\) be the \(n\) keys and values it can attend to. Queries and keys have dimension \(d\). We L2-normalize them to obtain \(\hat{\mathbf{q}}\) and \(\hat{\mathbf{k}}_i\).

Each attention layer learns a scalar \(\gamma\), initialized at zero. We use \(g=e^\gamma\) as a learned positive score multiplier, initially one. Exponentiating keeps it positive while allowing \(\gamma\) to take any real value. We use it to compute the scores

\[s_i=g\,\hat{\mathbf{q}}^\top\hat{\mathbf{k}}_i.\]

Linear and softmax attention turn these scores into outputs differently:

\[A_{\mathrm{linear}}(\mathbf{q})=\frac1n\sum_{i=1}^{n}s_i \mathbf{v}_i.\]
\[A_{\mathrm{softmax}}(\mathbf{q})=\frac{\sum_{i=1}^{n}e^{s_i}\mathbf{v}_i}{\sum_{i=1}^{n}e^{s_i}}.\]

For softmax, the multiplier acts as an inverse temperature: increasing it makes the weights more selective. If \(T\) denotes temperature, then \(g=1/T\).

The interactive figure below shows how each attention function maps a query to an output. It starts with unnormalized queries and keys, using scores \(s_i=g\mathbf{q}^\top \mathbf{k}_i/\sqrt d\). For fixed keys and values, linear attention is then linear in the query. Softmax bends this mapping and keeps the output inside the values’ convex hull. Turning on QK norm switches to the normalized scores used in training.

At first glance, softmax seems like the natural choice. It gives us a nonlinear response, and with suitable keys, values, and scales, it can approximate linear behavior locally. This is an intuition about flexibility rather than strict containment: softmax weights are positive and sum to one, while our linear attention uses signed weights.

Does the choice of attention function help on some tasks and hurt on others? We keep the architecture fixed, change the attention function, and compare the models on two tasks.

Two simple tasks

In-context linear regression

We adapt the in-context regression task of Ekin Akyürek et al.

For each sequence, we sample a new matrix \(\mathbf{W}\in\mathbb R^{2\times2}\) and generate examples using \(\mathbf{y}_i=\mathbf{W}\mathbf{x}_i\). The model sees eight input-output pairs, followed by a new input:

\[ (\mathbf{x}_1,\mathbf{y}_1),\ldots,(\mathbf{x}_8,\mathbf{y}_8),\mathbf{x}_9 \quad\longrightarrow\quad\hat{\mathbf{y}}_9. \]

Its task is to predict \(\mathbf{y}_9=\mathbf{W}\mathbf{x}_9\). We train with mean squared error, averaged over the two output coordinates.

Since \(\mathbf{W}\) changes between sequences, the model has to use the examples in its context to predict the new output.

Despite the shared name, linear attention does not generally compute the least-squares solution. The network has to learn how to infer a new mapping from the examples in each sequence. Softmax attention can do this too: Akyürek et al. show that trained softmax transformers can closely match ordinary least squares. Both of our networks also contain nonlinear operations. Whether replacing softmax with linear attention helps in this smaller architecture is therefore an empirical question, rather than something implied by the task’s name.

Lookup on an 8 × 8 grid

Here, there is no shared rule connecting coordinates to labels. Each sequence gives the model a new lookup table, and it must retrieve the label at the queried coordinate.

Each grid location has a label, either 0 or 1.

For each sequence, we generate fresh labels and show the model all 64 coordinate-label pairs in a random order. We then give it one of those coordinates again. Its task is to return the label that appeared with that coordinate.

Hover over the grid to choose a query. Here, (1/7, 1/7) should return 0. In the next sequence, that same coordinate could have a different label, so the model has to retrieve the answer from the current context.

Coordinates are evenly spaced from −1 to 1 on each axis. The exact numeric input format for both tasks is in the appendix.

The model outputs two scores, one for label 0 and one for label 1. We choose the label with the higher score. We train with cross-entropy and report the percentage of queries answered correctly.

Model and training

We use the same architecture for both tasks and all three attention types: \(N=6\) residual attention blocks of width 32, followed by an attention readout. The models have about 27,000 parameters. In the diagram, \(\mathbf{H}^{(\ell)}\) denotes the sequence of hidden states entering block \(\ell\).

All attention operations are causal, including the current token itself, and use QK normalization with the learned multiplier defined above.

The blocks also contain RMSNorm and ReLU, so a network using linear attention is not globally linear.

For the main comparisons, we use a batch size of 1,024 and perform 10,000 updates, using seeds 0–2. We tune peak learning rate separately for each task and attention type. The rest of the optimizer settings are shared.

We first compare linear and softmax attention. Hover over the curves to inspect a validation point, or select a seed.

Linear attention reaches lower error on regression, while softmax reaches higher accuracy on lookup. The direction holds on every seed, after tuning the learning rate separately for each task and attention type.

Wang, Shi, and Fox interpret attention as regression from keys to values. Linear attention gives the same prediction as starting a linear map at zero, taking one least-squares gradient step, and applying it to the query. In our formulation, the multiplier (g) acts as that step’s size when the loss is averaged over keys. This generally does not solve least squares exactly. QK-normalized softmax attention instead predicts a locally weighted average of the values. These interpretations describe the attention operation on internal features, rather than the full network’s learning algorithm.

Is linear attention simply more data-efficient on this task, or does it also reach a better solution with more training? We increase the training budget tenfold, scaling the peak learning rate down by \(\sqrt{10}\). Linear attention still finishes with lower error in this seed-0 experiment. Full details and alternative schedules are in the appendix.

Softmax has a nonlinear response, but linear attention still learns this regression task with lower error. Minimum description length expresses a preference for explanations whose complexity is justified by the data. Here, we use that idea as motivation, rather than measuring description length. We would like a parameterization that can learn either kind of response, with an initialization that favors a simple solution.

Learning the attention function

Look again at the two attention operations. We can write both as a weighted sum divided by a sum:

\[A_{\mathrm{linear}}(\mathbf{q})=\frac{\sum_i s_i \mathbf{v}_i}{\sum_i 1}.\]
\[A_{\mathrm{softmax}}(\mathbf{q})=\frac{\sum_i e^{s_i}\mathbf{v}_i}{\sum_i e^{s_i}}.\]

The difference is in how they transform the scores. Let \(G\) transform the score multiplying each value, and let \(H\) transform the scores used for normalization. This gives the more general form

\[A(\mathbf{q})=\frac{\sum_{i=1}^{n}G(s_i)\mathbf{v}_i}{\sum_{i=1}^{n}H(s_i)}.\]

Choosing \(G(s)=s\) and \(H(s)=1\) gives linear attention. Choosing \(G(s)=H(s)=e^s\) gives softmax. But we do not have to fix either transformation in advance, or require them to be the same.

We parameterize both functions with learned polynomials. Let \(P\) be the degree, the highest available power of the score. Writing \(r\) for the power and \(a_r\) and \(b_r\) for its coefficients, we fix the constant term of \(H\) at one and use

\[ G(s)=\sum_{r=0}^{P}a_rs^r,\qquad H(s)=1+\sum_{r=1}^{P}b_rs^r. \]

Each attention block and the readout learns its own coefficients. The constant term of \(H\), which we call \(b_0\), stays fixed at one. We use \(P=8\) in our experiments. The denominator sums \(H\) over the visible keys; the resulting attention weights can be signed and need not sum to one.

This family contains linear attention exactly. It can also approximate softmax: define the truncated exponential

\[T_P(s)=\sum_{r=0}^{P}\frac{s^r}{r!}.\]

Setting \(G=H=T_P\) replaces the exponential in softmax with its Taylor polynomial. At finite degree this is an approximation, whose accuracy depends on the score range.

The animation below moves the coefficients between linear attention and truncated softmax. You can move the query, keys, or values while it runs. Change a coefficient to take over, or use Interpolate to pause and restart. Numerator coefficients change each value’s signed contribution; denominator coefficients change the shared normalization. The degree controls how many powers of the score are available. These controls edit the function directly, without retraining a model.

Learning these functions is related to Kolmogorov–Arnold Networks (KANs), which learn univariate spline functions on network edges. Our construction instead learns polynomial functions of attention scores.

Polynomial attention itself is not a new idea. PolySketchFormer studies polynomial kernels and sketching, while TaylorShift develops efficient computations for second-order Taylor-softmax. Both normalize with the same polynomial response used to weight the values. Here, the numerator and denominator have independent learned coefficients, starting from linear attention.

Starting from linear attention

We initialize every attention layer to linear attention:

\[G(s)=s,\qquad H(s)=1.\]

We set \(a_1=1\) and all other trainable coefficients to zero. Each layer starts with the same attention operation as the linear model, while the additional terms can change from the first update. We encourage a simple solution through linear initialization.

Keeping the denominator stable

Training this parameterization directly can be unstable. Some runs learn successfully, while others produce nonfinite losses. To understand why, write the denominator for query \(\mathbf{q}\) as

\[D(\mathbf{q})=\sum_{i=1}^{n}H(s_i).\]

At linear initialization, \(H(s)=1\), so \(D(\mathbf{q})=n\). As the coefficients change, positive and negative terms can cancel. If their sum reaches zero, the attention output divides by zero.

We sweep learning rates for direct polynomial training on both tasks. Nine of the 30 runs produce a nonfinite result. In the five failures we inspect, the scores and numerator remain finite, but the computed denominator reaches exactly zero. The right panel shows one such failure: the smallest denominator magnitude per visible key, \(|D(\mathbf{q})|/n\), across queries and layers.

The solution is to keep \(H\) close enough to one over the possible scores that these terms cannot cancel. Let \(\rho\) be a fixed hyperparameter controlling its allowed deviation, with \(0<\rho<1\). We want \(|H(s)-1|\le\rho\) for every score a layer can produce.

QK normalization gives us that score range. The normalized query and key have norms at most one, so Cauchy–Schwarz gives \(|s|\le g\). Define a coefficient budget

\[m=\sum_{r=1}^{P}|b_r|g^r.\]

This budget bounds the deviation of \(H\) from one. By the triangle inequality,

\[ \begin{aligned} |H(s)-1|&=\left|\sum_{r=1}^{P}b_rs^r\right|\\ &\le\sum_{r=1}^{P}|b_r|\,|s|^r \le\sum_{r=1}^{P}|b_r|g^r=m. \end{aligned} \]

After each optimizer update, we compute \(m\) using the updated multiplier and coefficients. If \(m>\rho\), we multiply all nonconstant denominator coefficients by \(\rho/m\). Otherwise, we leave them unchanged. This rescaling ensures \(m\le\rho\). The constant term stays at one, and the multiplier and numerator coefficients are unchanged by the rescaling.

Every denominator term now lies between \(1-\rho\) and \(1+\rho\). Summing over the \(n\) visible keys gives

\[n(1-\rho)\le D(\mathbf{q})\le n(1+\rho).\]

We use \(\rho=0.5\), so the denominator stays between \(n/2\) and \(3n/2\). This keeps it positive and away from zero without clamping the forward computation. The same rule applies to every block and the readout, on both tasks. It restricts the denominator’s variation while leaving the numerator coefficients free.

We call this update the denominator projection. The playground above allows free coefficient edits; training uses this additional constraint. Below, we compare the learning-rate sweeps with and without projection. Crosses mark runs that produce nonfinite results; the diagnostic details are in the appendix.

Why start linear?

We next change the initialization while keeping the polynomial parameterization fixed. Linear attention is still expressible, so training could in principle recover it from another starting point.

We test this on in-context linear regression. Instead of initializing \(G(s)=s\) and \(H(s)=1\), we initialize both functions to the degree-eight approximation of the exponential introduced above: \(G=H=T_8\). The polynomial family stays the same; only its starting coefficients change.

We use the same training setup for both initializations. We also widen the denominator bound to \(\rho=1.8\) for both, so that neither starting function needs to be rescaled to satisfy the constraint at initialization. The original-bound comparison is in the appendix.

Linear initialization finishes with lower error on all three seeds. The linear attention function is available under either initialization, but starting elsewhere does not recover the same performance within this training budget. Even with the same parameterization, changing the initialization changes the final error.

Starting linear helps on this task. We have not measured whether the runs end up in different basins or whether their final attention functions differ in simplicity. The landscape illustrates the idea; it is not a measurement of these models.

Appendix: the experiments

All attention types are evaluated with dense attention matrices; we study learned behavior rather than computational speedups. The attention comparisons use the final main runs; the initialization comparison is a separate set of matched reruns. The results include 18 main runs, eight stabilization ablations, 270 main LR sweep runs, 12 initialization runs, nine longer-training runs, and 30 additional runs without denominator projection. The failure analysis examines five of the nine failed unprojected runs.

Task data, input encoding, and losses

Linear regression

For each sequence, the entries of \(\mathbf{W}\in\mathbb R^{2\times2}\) are drawn independently from \(\mathcal N(0,1/2)\). We independently sample nine inputs \(\mathbf{x}_i\) uniformly from \([-1,1]^2\), and set \(\mathbf{y}_i=\mathbf{W}\mathbf{x}_i\).

Each of the eight example tokens is \([x_{i,1},x_{i,2},y_{i,1},y_{i,2},1]\). The ninth token is \([x_{9,1},x_{9,2},0,0,0]\), withholding the query’s answer. The input has nine tokens with five fields each.

For a batch of \(B\) sequences, superscript \((b)\) identifies the sequence. Training and validation use mean squared error over both output coordinates:

\[ \mathcal L_{\mathrm{reg}}=\frac{1}{2B}\sum_{b=1}^{B} \big\|\hat{\mathbf{y}}_9^{(b)}-\mathbf{y}_9^{(b)}\big\|_2^2. \]

For comparison, let \(\mathbf{U}\) be a candidate regression matrix fitted to the \(n=8\) context examples. Its ordinary least-squares objective and a gradient-descent update with step size \(\eta\) are

\[ \begin{gathered} J(\mathbf{U})=\frac{1}{2n}\sum_{i=1}^{n}\|\mathbf{U}\mathbf{x}_i-\mathbf{y}_i\|_2^2,\\[.5em] \mathbf{U}^{(t+1)}=\mathbf{U}^{(t)}-\frac{\eta}{n}\sum_{i=1}^{n} (\mathbf{U}^{(t)}\mathbf{x}_i-\mathbf{y}_i)\mathbf{x}_i^\top. \end{gathered} \]

Akyürek et al. give constructive implementations of single-example gradient updates and closed-form ridge regression in transformers. The equation above illustrates full-batch gradient descent. Our networks are trained on query prediction error; we do not assume they implement either algorithm.

Lookup

The coordinate values on each axis are \(-1+2j/7\) for \(j=0,\ldots,7\), stored in float32. Fractions in the figure denote the ideal grid coordinates. Every sequence contains all 64 coordinate pairs in shuffled order. Each coordinate receives an independent label \(y_i\sim\operatorname{Bernoulli}(1/2)\). We choose one of the 64 records uniformly as the query.

Writing the coordinate as \(\mathbf{x}_i=(x_{i,1},x_{i,2})\), its record is \([x_{i,1},x_{i,2},1-y_i,y_i,1]\). The query is \([x_{j,1},x_{j,2},0,0,-1]\), and the target is \(y_j\). Thus every input has 65 tokens with five fields each.

For sequence \(b\), let \(t_b\in\{0,1\}\) be its target and \(\mathbf{z}_b=(z_{b,0},z_{b,1})\) the model’s two scores. We use cross-entropy and report classification accuracy:

\[ \mathcal L_{\mathrm{lookup}}=-\frac1B\sum_{b=1}^{B} \log\big[\operatorname{softmax}(\mathbf{z}_b)\big]_{t_b}. \]
\[ \operatorname{accuracy}=\frac1B\sum_{b=1}^{B} \mathbf1\!\left\{\arg\max_{c\in\{0,1\}}z_{b,c}=t_b\right\}. \]

The side figure uses a sequence generated by this same data generator. Its records are arranged spatially only for illustration; the model receives shuffled numeric records.

Polynomial ablations

We rerun seed 2 on each task at its selected polynomial LR. “No extras” uses neither projection nor coefficient freezing. “Freeze only” holds the coefficients for the first 1,000 updates without projection. “Projection + freeze” adds that hold to the final projected recipe. The final arm adds degree-weighted coefficient regularization with \(\lambda=0.01\) to projection alone, with no freezing. We do not retune LR separately for these ablations.

Without the denominator projection, the lookup “no extras” run becomes nonfinite. We report that as a failure, not as a final accuracy. The freeze-only lookup run finishes at 61.73%; projection alone, projection plus freezing, and projection plus regularization all reach 100% for this seed.

For the regularization arm, let \(\ell\) index the six attention blocks and the readout. The coefficients \(a_{\ell,r}\) and \(b_{\ell,r}\) belong to layer \(\ell\). With \(\mathcal L_{\mathrm{task}}\) denoting the task loss, the regularized objective is

\[ \begin{gathered} \mathcal R=\sum_{\ell}\left[a_{\ell,0}^{2}+\sum_{r=2}^{8}r^2a_{\ell,r}^{2}+\sum_{r=1}^{8}r^2b_{\ell,r}^{2}\right],\\[.5em] \mathcal L_{\mathrm{train}}=\mathcal L_{\mathrm{task}}+\lambda\mathcal R. \end{gathered} \]

The linear numerator coefficient \(a_1\) is unpenalized and \(b_0=1\) is fixed. This is an optional ablation; \(\lambda=0\) in every main polynomial result above.

Training sequences remain freshly sampled from the same distribution, so the longer runs also see ten times as many training sequences. Context lengths are unchanged.

“Stretched schedule” uses the selected peak LRs: linear 0.0113137, softmax 0.004, and polynomial 0.008. It holds the peak for 60,000 updates, then uses cosine decay over the remaining 40,000. “Cosine from start” uses peak LR 0.004 for all three models and decays over the full 100,000 updates. “Scaled peak” divides each selected peak LR by \(\sqrt{10}\) and uses the stretched schedule. Initialization comparisons

Both initialization comparisons use seeds 0–2, batch size 1,024, 10,000 updates, and the same flat-then-cosine schedule with peak LR 0.008. We do not retune LR for each initialization. Why compare two denominator bounds?

At \(g=1\), the truncated-softmax denominator has coefficient budget \(\sum_{r=1}^{8}1/r!\approx1.7183\). It starts outside the main recipe’s bound of 0.5, so the projection rescales its denominator coefficients after the first update.

We therefore repeat both initializations with a bound of 1.8, which admits the truncated-softmax initialization unchanged. This wider bound no longer guarantees a positive denominator throughout training. All six runs finish with finite validation losses. The other settings are identical within each comparison: degree eight, no coefficient freezing, no coefficient regularization, and the same flat-then-cosine schedule.

Unprojected training and denominator failures

The extra unprojected sweep uses seed 2, the same 15 peak LRs, batch size 1,024, and the original 10,000-update flat-then-cosine schedule. Only the denominator projection is removed. No coefficients are frozen or regularized. Thirteen regression runs and eight lookup runs finish with finite results. The other nine runs produce a nonfinite training or validation result.

The projected comparison in Figure 8 uses seed 2 from the original LR sweep. Its hardware is H100, while the unprojected sweep uses an RTX 2080 Ti. It is a comparison of these recorded sweeps, not a perfectly hardware-matched intervention.

For the five diagnosed failures, same-GPU replays match all saved measurements in the checked prefixes and replay windows. We retain the original forward arithmetic and inspect the actual sum over visible keys, not just roots of the polynomial. In every examined case, finite scores and numerator values precede a zero computed denominator. The four other failures are not diagnosed.

As a separate numerical check, we rescale only the denominator coefficients at each saved pre-failure checkpoint, then apply the normal projection after subsequent updates. All five short diagnostic windows remain finite. These interventions are stability checks, not complete retrainings or evidence of final task performance.

Simplicity, MDL, and Bayesian Occam’s razor

One way to express a preference for simple explanations is to minimize a complexity measure \(C(f)\) among functions with equally good or nearly equally good data fit. Let \(\mathcal L_D\) be the loss on dataset \(D\), and let \(\mathcal L_D^\star=\inf_f\mathcal L_D(f)\) be its best possible value. A tolerance \(\varepsilon\ge0\) specifies how close a fit must be to that value. One possible formulation is

\[ f^\star\in\underset{f:\,\mathcal L_D(f)\le\mathcal L_D^\star+\varepsilon}{\arg\min}C(f). \]

This expresses a preference; it is not the objective we optimize in these experiments.

In two-part MDL, a hypothesis \(h\) costs \(L(h)\) bits to describe, and the data cost another \(L(D\mid h)\) bits when encoded using it. With the coding rules fixed, the selected hypothesis minimizes

\[h_{\mathrm{MDL}}\in\arg\min_h\big[L(h)+L(D\mid h)\big].\]

Bayesian Occam’s razor gives a related model-selection perspective. For model family \(\mathcal M\), parameter \(\theta\), prior \(p(\theta\mid\mathcal M)\), and likelihood \(p(D\mid\theta,\mathcal M)\), the model evidence is

\[ p(D\mid\mathcal M)=\int p(D\mid\theta,\mathcal M)\,p(\theta\mid\mathcal M)\,d\theta. \]

It averages fit over the prior rather than considering only the best-fitting parameters. A flexible model whose good fits occupy little prior probability can therefore have lower evidence. This depends on the prior and is not an automatic preference for fewer parameters. Our runs do not perform Bayesian inference or measure evidence; the connection is motivational.

Related work

The simplicity framing above draws on Grünwald’s MDL tutorial, the simplicity bias of the parameter-function map, spectral bias, and low-rank simplicity bias. These concern different measures of simplicity and do not establish that training minimizes description length. In a more specialized setting, Mușat proves an asymptotic relation between minimum weight norms and Kolmogorov complexity, with a logarithmic factor, for constant-precision looped networks. This is a statement about minimum-norm representations, not a guarantee that gradient-based training finds them. The in-context regression setting follows the line of work represented by Akyürek et al.

Test-time regression connects sequence layers to parametric and nonparametric regression. Its higher-order local polynomial regression construction is different from our learned polynomials of attention scores. KAN is another precedent for replacing fixed nonlinearities with learned functions, using splines on network edges.

For attention, Katharopoulos et al. develop kernel-feature attention that can be evaluated recurrently. Their construction uses nonnegative similarities and normalizes by their sum; our baseline uses signed dot products and divides by the number of visible keys. Random Feature Attention approximates softmax through random features. PolySketchFormer and TaylorShift study polynomial/Taylor attention and its efficient evaluation. BASED studies the state-size/recall tradeoff. Our emphasis here is the relationship between the task, the attention parameterization, and its initialization.

There is also prior work on simplicity bias in attention itself. Zhang, Saxe, and Latham study saddle-to-saddle dynamics and the progressive recruitment of effective attention heads in their analyzed models. Our head count is fixed; we vary the attention function and its initialization. Learning the Transformer Kernel learns a kernel’s spectral distribution, and ReBased learns affine transformations of queries and keys within a quadratic-kernel construction to improve in-context recall. These are close precedents for letting the attention kernel adapt. Our experiments use independent degree-eight numerator and denominator polynomials, initialized to the signed linear operator, and compare the learned behavior on two contrasting tasks.
